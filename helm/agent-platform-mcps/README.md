| agentgateway.oauthMode | string | `"passthrough"` | OAuth discovery and edge validation mode.  muster serves all OAuth discovery paths natively (/.well-known/oauth-protected-resource, /.well-known/oauth-authorization-server, etc.) because clients dial the muster hostname directly. | identityProviders | object | `{}` | Identity providers, defined once and referenced by servers via auth.provider. Multiple servers on the same cluster share one entry instead of repeating token-exchange config.  expectedIssuer pins the `iss` claim of the exchanged token. It is required when tokenEndpoint points at a transport-only proxy (e.g. a tunnelport `:8443` in-cluster Service) whose URL differs from the remote Dex issuer: the minted token still carries the public Dex issuer, so muster must be told what to expect. When tokenEndpoint is the real public Dex URL it can be omitted (muster derives the issuer from tokenEndpoint).  Example (tunneled):   cluster-b:     tokenEndpoint: https://dex-cluster-b.agent-platform.svc.cluster.local:8443/token     expectedIssuer: https://dex.cluster-b.example.com     connectorId: giantswarm-simple-oidc     scopes: openid profile email groups     credentialsSecret:       name: cluster-b-token-exchange-credentials       namespace: muster        # optional; defaults to the release namespace       clientIdKey: client-id       clientSecretKey: client-secret |
| mcpServers | list | `[]` | Flat list of MCP servers. Required fields per entry: cluster, group, url. Optional: name (default <cluster>-mcp-<group>), namespace (default: the release namespace), transport, autoStart, timeout, toolPrefix, auth. The entry schema is closed: a key the chart does not read fails the values check instead of being dropped silently.  auth.mode selects how muster authenticates to the server: none, oauth (muster runs its own OAuth login against the server's authorization server and holds the person's grant), forward (the caller's Dex token, same-cluster only) or exchange (RFC 8693 via identityProviders). For mode oauth, auth.authorizationServer pins an authorization server muster can neither discover nor register with (GitHub) -- rendered into spec.auth.authorizationServer as is; needs the muster chart >= 5.8.0, an older CRD prunes the pin silently. issuer is required; authorizationEndpoint and tokenEndpoint go together (both or neither, the CRD's rule); grantScope is session (default) or subject; clientCredentialsSecretRef.namespace defaults to the MCPServer's namespace. Keys other than these fail the render.  Example entries:   # Same-cluster server, the Dex token forwarded as-is.

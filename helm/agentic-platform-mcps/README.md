## Values

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| agentgateway | object | `{"enabled":false,"gateway":{"name":"agentgateway"},"jwt":{"audiences":["dex-k8s-authenticator"],"extraProviders":[],"issuer":"","jwksBackendRef":{"name":"dex","namespace":"giantswarm","port":5556},"jwksPath":"/keys"},"musterUrl":"","oauthMode":"passthrough","tokenExchange":{"broker":{"kind":"Service","name":"muster-token-exchange-broker","namespace":"muster","port":8080,"protocol":"grpc"}},"viaMuster":false}` | Render agentgateway CRs for the via-muster topology. When viaMuster is true the traffic flow is:   client → agentgateway → muster → N MCP servers agentgateway becomes the single MCP choke point for observability (per-call metrics, traces, access logs). muster keeps all per-server connection logic, OAuth, and RFC 8693 token exchange. |
| agentgateway.enabled | bool | `false` | Enable agentgateway CR rendering. |
| agentgateway.gateway | object | `{"name":"agentgateway"}` | Name of the agentgateway data-plane Gateway CR in the release namespace. An HTTPRoute is rendered on this Gateway connecting it to the AgentgatewayBackend. The public ingress HTTPRoute (cluster ingress → agentgateway Service) is owned by the agentic-platform umbrella chart (gateway.httpRoute). |
| agentgateway.jwt | object | `{"audiences":["dex-k8s-authenticator"],"extraProviders":[],"issuer":"","jwksBackendRef":{"name":"dex","namespace":"giantswarm","port":5556},"jwksPath":"/keys"}` | JWT validation config — only used when oauthMode: validate. agentgateway fetches the JWKS from the named Kubernetes Service to verify inbound tokens locally (cached after first fetch; no per-request network call). Points at Dex, the token issuer (muster never signs tokens). |
| agentgateway.jwt.audiences | list | `["dex-k8s-authenticator"]` | Expected `aud` claim values. The downstream server's expected audience (e.g. dex-k8s-authenticator). |
| agentgateway.jwt.extraProviders | list | `[]` | Additional JWT providers, rendered verbatim into the jwtAuthentication providers list after the primary provider above. Use to accept tokens from a second issuer at the edge, e.g. Dex ID tokens from a different connector alongside the primary Dex provider. Cross-namespace jwks backendRefs require a ReferenceGrant in the target namespace (kind AgentgatewayPolicy, group agentgateway.dev). Example:   extraProviders:     - issuer: https://dex.<codename>.<base>       audiences: [<backstage-dex-client-id>]       jwks:         remote:           backendRef: {name: dex, namespace: giantswarm, port: 5556}           jwksPath: /keys |
| agentgateway.jwt.issuer | string | `""` | OIDC issuer URL. Must match the `iss` claim in inbound tokens. Dex: https://dex.<codename>.<base> |
| agentgateway.jwt.jwksBackendRef | object | `{"name":"dex","namespace":"giantswarm","port":5556}` | Kubernetes Service reference for the JWKS endpoint. |
| agentgateway.jwt.jwksPath | string | `"/keys"` | Path on the JWKS Service where public keys are served. Dex: /keys |
| agentgateway.musterUrl | string | `""` | In-cluster muster aggregator endpoint. Required when viaMuster: true. Typically http://<release>-muster.<namespace>.svc.cluster.local:8090/mcp |
| agentgateway.oauthMode | string | `"passthrough"` | OAuth discovery and edge validation mode.  muster serves all OAuth discovery paths natively (/.well-known/oauth-protected-resource, /.well-known/oauth-authorization-server, etc.) because clients dial the muster hostname directly. No proxy HTTPRoute is needed.  passthrough (current default): agentgateway forwards all tokens to muster   without inspecting them. muster is the sole enforcement point.  validate: additionally renders an AgentgatewayPolicy with jwtAuthentication   pointing at the JWKS endpoint, attached to this chart's MCP HTTPRoute (not the   shared Gateway, which also carries other charts' routes). agentgateway validates   the inbound token before forwarding. muster still validates downstream (defence in depth).   Validates against Dex's JWKS (the token issuer); muster never signs tokens.   agentgateway v1.2.1+ serves /.well-known/oauth-protected-resource and emits   WWW-Authenticate without a provider preset — no blocker. |
| agentgateway.tokenExchange | object | `{"broker":{"kind":"Service","name":"muster-token-exchange-broker","namespace":"muster","port":8080,"protocol":"grpc"}}` | Outbound token-exchange broker for auth.mode=exchange servers. One AgentgatewayPolicy per exchange target is rendered, delegating cross-cluster token exchange to this ext_authz service. Not used when viaMuster: true (muster handles all exchange internally). |
| agentgateway.viaMuster | bool | `false` | Route all MCP traffic through muster as a single backend instead of connecting agentgateway directly to each server. Requires muster.enabled: true. |
| defaults | object | `{"audiences":["dex-k8s-authenticator"],"autoStart":true,"transport":"streamable-http"}` | Defaults applied to every mcpServers entry unless overridden per entry. |
| defaults.audiences | list | `["dex-k8s-authenticator"]` | Audiences required at the upstream for oauth-authenticated servers. |
| defaults.autoStart | bool | `true` | Start connections automatically when muster starts. |
| defaults.transport | string | `"streamable-http"` | MCP transport protocol. |
| identityProviders | object | `{}` | Identity providers, defined once and referenced by servers via auth.provider. Multiple servers on the same cluster share one entry instead of repeating token-exchange config.  expectedIssuer pins the `iss` claim of the exchanged token. It is required when tokenEndpoint points at a transport-only proxy (e.g. a tunnelport `:8443` in-cluster Service) whose URL differs from the remote Dex issuer: the minted token still carries the public Dex issuer, so muster must be told what to expect. When tokenEndpoint is the real public Dex URL it can be omitted (muster derives the issuer from tokenEndpoint).  Example (tunneled):   cluster-b:     tokenEndpoint: https://dex-cluster-b.agentic-platform.svc.cluster.local:8443/token     expectedIssuer: https://dex.cluster-b.example.com     connectorId: giantswarm-simple-oidc     scopes: openid profile email groups     credentialsSecret:       name: cluster-b-token-exchange-credentials       namespace: muster        # optional; defaults to the release namespace       clientIdKey: client-id       clientSecretKey: client-secret |
| mcpServers | list | `[]` | Flat list of MCP servers. Required fields per entry: cluster, group, url.  Example entries:   # Same-cluster server, the Dex token forwarded as-is. The backend   # validates it against Dex's JWKS; muster is not an issuer.   - cluster: graveler     group: kubernetes     url: https://mcp-kubernetes.graveler.example.com/mcp     auth:       mode: forward    # Remote cluster server, RFC 8693 token exchange via identityProviders:   - cluster: gazelle     group: kubernetes     url: https://mcp-kubernetes.gazelle.example.com/mcp     auth:       mode: exchange       provider: gazelle          # ref into identityProviders above    # Unauthenticated server:   - cluster: graveler     group: prometheus     url: https://mcp-prometheus.graveler.example.com/mcp     auth:       mode: none |
| muster | object | `{"enabled":true,"families":{"kubernetes":{"instanceArg":"management_cluster"},"prometheus":{"instanceArg":"management_cluster"}}}` | Render muster MCPServer CRs from the mcpServers list. |
| muster.enabled | bool | `true` | Enable muster MCPServer rendering. |
| muster.families | object | `{"kubernetes":{"instanceArg":"management_cluster"},"prometheus":{"instanceArg":"management_cluster"}}` | Groups that muster exposes as instance families. A server whose `group` is listed here gets a muster `family` block; unlisted groups are singletons. |
